## 2. 术语

| 术语 | 含义 |
|---|---|
| 主包AI | 打开「免费外包」的 AI-Agent 工具（首发 ThinCoder 桌面版）——任务的发布方 |
| 宿主 | 承载主包AI 的 MCP 客户端程序（如 ThinCoder 桌面版）——仅在传输 / 进程语境使用，不指代任务发布方 |

## 3. 需求条目

### R1 「免费外包」可被 AI 工具调用（MCP 接入）〔台账 #1｜批次 b1〕

**模块目标**：让支持 MCP 的 AI 工具能在设置里添加「免费外包」并调用它的全部能力。

**功能点**

- F1.1 应用内起一个仅本机可访问的 MCP 服务端点（默认 `http://127.0.0.1:17873/mcp`）。
- F1.2 端点提供 initialize 握手与工具清单（六件套：派单 / 查单 / 取件 / 列外包工 / 取消 / 附件）。
- F1.3 支持宿主以 URL 型配置接入：ThinCoder「设置 → MCP」新增；项目根 `.mcp.json`（`mcpServers` 对象形）作为第二源。
- F1.4 提供探活接口 `GET /healthz`（返回 ok / 版本 / 端口 / 外包工概览）。

**边界（不做）**：不做公网或局域网访问（只绑 127.0.0.1）；不针对某一宿主做私有插件或私有协议；b1 不提供 stdio 命令型接入（利弊与触发条件见设计档）。

**验收**

- AC-R1-1（操作可证伪）：先在项目根写 `.mcp.json` 指向端点，再在 ThinCoder「设置 → MCP」完成探活，Tools 列表出现六个工具。
- AC-R1-2（命令可验）：`npm run verify:mcp` 断言 initialize 成功、tools/list 恰好返回六件套、每个工具入参 schema 齐全。
- AC-R1-3（命令可验）：从非 127.0.0.1 地址访问端点失败（连接被拒）。

**依赖**：宿主支持 MCP（已实测：ThinCoder 桌面版有 MCP 段，配置落 `config.json` 的 `mcp.servers`，另支持项目根 `.mcp.json` 第二源）；本机端口可用。

### R2 「主包AI」称谓与角色约定〔台账 #2｜批次 b1〕

**模块目标**：统一「谁在调用本工具」的称呼，避免文档、界面与接口各自造词。

**功能点**

- F2.1 全库文档、界面文案、MCP 工具描述统一使用「主包AI」指代调用方。
- F2.2 MCP 工具的 description 与错误提示面向主包AI 书写（中文、含下一步建议）。

**边界**：这是命名与文案约定，不引入运行时角色系统（不做多用户 / 权限模型）。

**验收**

- AC-R2-1（命令可证伪）：检索范围为 `docs/**`、`src/**` 与界面词表（UI 文案常量）；凡指代调用方的表述一律为「主包AI」，术语表已定义的「宿主」（MCP 客户端容器）为唯一例外；同一角色出现第二个称谓即判失败。
- AC-R2-2（命令可验）：`tools/list` 返回的每个工具 description 非空且为中文。

**依赖**：无。

### R3 核心闭环：派单 → 网页版执行 → 取回文件〔台账 #3｜批次 b1〕

**模块目标**：主包AI 交来一条任务后，本工具在本地打开网页版 AI（首发 DeepSeek）执行，并把答复与产出文件取回本机交付目录。

**功能点**

- F3.1 派单：接收任务文本（可选：指定外包工、附件文件、等待时长），立即返回任务号（异步任务模型）。
- F3.2 执行：按外包工适配器开启新会话 →（有附件则）上传 → 发送任务文本。
- F3.3 取答复：主通道 = 拦截平台流式响应体解析全文，以流内结束标记判定答完；DOM 抓取为兜底。
- F3.4 取文件（三层）：① 浏览器下载捕获并**自动落盘**（下载事件仍触发，机制细节见设计档）；② 回复内代码块提取（按首行 `# file: <名>` / `<!-- file: <名> -->` 命名）；③ 回复全文落盘。
- F3.5 交付：每单一个 outbox 子目录（manifest.json + answer.md + files/）；默认交付目录 = 配置值（出厂 `D:\免费外包\outbox\`，可改）。
- F3.6 送件（决策 H）：附件随派单上传给网页版 AI，回执中可见附件已送出。

**边界**：不代用户登录、不保存平台账号密码（登录态只存在浏览器配置目录）；不改动平台侧数据；不保证平台额度与可用性；不做内容审查与二次改写（原文取回）；平台服务条款与风控风险由用户自行判断。

**验收**

- AC-R3-1（命令可验）：`npm run verify:loop` 派一条含文件命名注释的最小任务，≤180 秒内任务终态 done；`<outbox>/<taskId>/` 下 manifest.json 状态 done、answer.md 非空、files/ 至少 1 个文件。
- AC-R3-2（命令可验）：同一次任务的 manifest 中取答复通道记为流通道（`delivery.transport = "sse"`），与 `probe/out3/raw-sse.txt` 描述的协议一致。
- AC-R3-3（命令可验）：`npm run verify:engine` 用本地 blob 页面复现「下载捕获 → 自动落盘」（探针 2 / 探针 6 已验证机制的回归）。
- AC-R3-4（命令可验）：派单带 1 个 .txt 附件，任务执行后 manifest.request.files 含该文件，且页面显示文件名（探针 2 已验证机制）。
- AC-R3-5（操作可证伪）：断网或登录失效时任务不静默卡死——在阶段超时上限内落到 failed / needs_human，并携带错误码。

**依赖**：浏览器可用（随包 Chromium 或系统 Edge）；平台登录态有效；网络可达平台。

### R4a 默认按优先级使用外包工〔台账 #4·前半｜批次 b1〕

**模块目标**：主包AI 未指定外包工时，按用户在界面里排定的优先顺序选人。

**功能点**

- F4a.1 优先级 = 界面上外包工列表的先后顺序（自上而下即第一、第二…）。
- F4a.2 未指定时选「当前可用（启用、健康、未满载）中优先级最高」的外包工；首选忙碌则排队等待，不因忙碌换人。
- F4a.3 首选不可用（未登录 / 风控 / 页面结构异常 / 启动失败）时降级到下一优先级，任务记录降级原因。

**边界**：不做多外包工拼单（一单只在一个外包工执行）；不按「质量猜测」换人。

**验收**

- AC-R4a-1（命令可验）：列表顺序 [A, B] 时不指定派单 → 任务 manifest.worker 为 A，selection.mode = "priority"。
- AC-R4a-2（操作可证伪）：让 A 处于未登录态 → 再派单 → 任务由 B 完成，manifest.attempts 记录 A 的失败原因与降级过程。
- AC-R4a-3（命令可验）：A 正忙（执行中）时再派一单 → 新单排队等待，不会自动转给 B（判据：manifest.worker 仍为 A）。

**依赖**：界面已配置至少一个外包工（b2 提供界面；b1 以配置文件充当）。

### R4b 按主包AI 要求指定调用已登记网页〔台账 #4·后半｜批次 b1〕

**模块目标**：主包AI 可以点名使用用户在界面中登记过的某个外包工（用自定义名指定）。

**功能点**

- F4b.1 派单入参 `worker` 支持用「自定义名」（或条目 id）指定。
- F4b.2 指定只命中用户已登记的条目；未登记的名字一律拒绝（错误码 + 可用名单提示）。
- F4b.3 指定 = 硬绑定：指定对象不可用时明确报错，不静默换人。

**边界**：不能指定未在界面出现的平台；不能绕过界面录入（不支持用 URL 或任意描述代替名字）。

**验收**

- AC-R4b-1（命令可验）：`dispatch_task({worker: "<自定义名>"})` → manifest.worker.name 为该名、selection.mode = "explicit"。
- AC-R4b-2（命令可验）：`dispatch_task({worker: "不存在"})` → 返回错误码 E_WORKER_UNKNOWN 并提示可用名单；任务不创建。
- AC-R4b-3（命令可验）：指定处于未登录态的外包工 → 任务落到 needs_human / E_LOGIN_REQUIRED（或 E_WORKER_UNAVAILABLE），不得由其他外包工完成。

**依赖**：同 R4a。

### R5 设置界面四件事：新增 / 删除 / 调序 / 自定义名〔台账 #5｜批次 b2〕

**模块目标**：用户用一个简洁界面管理外包工清单，不需要手改配置文件。

**功能点**

- F5.1 新增外包工（选平台；b1 起 DeepSeek 可选，**b3 起 Kimi 亦可选**）；界面为独立设置窗口，应用托盘常驻（决策 D）。
- F5.2 删除外包工（二次确认）。
- F5.3 调整优先顺序（列表上移 / 下移）。
- F5.4 外包工自定义名（列表内唯一），即主包AI 指定调用时使用的名字。
- F5.5 显示每个外包工的登录状态与最近检查时间。
- F5.6 改动即时落盘并生效（无需重启）。
- F5.7 交付目录设置：显示当前**实际**路径（默认按交付策略解析）、可修改、可一键打开；网页端下载的文件与答复文本都落于该目录下每单的子目录内（下载文件不再别处默认落点）。

**边界**：不做账号体系（不管理平台账号密码）；不做平台侧设置；不做主题 / 皮肤类定制。

**验收**

- AC-R5-1（操作可证伪）：界面新增一个外包工 → config.json 出现该条目且 `list_workers` 可见。
- AC-R5-2（操作可证伪）：删除 → 条目消失、不再出现在 `list_workers`，且删除前有确认框。
- AC-R5-3（操作可证伪）：上下调序 → config.json 数组顺序变化；不指定派单的选人随之变化（复测 AC-R4a-1）。
- AC-R5-4（操作可证伪）：改名 → 用新名派单成功、旧名返回 E_WORKER_UNKNOWN。
- AC-R5-5（操作可证伪）：重启应用后以上改动保留。
- AC-R5-6（操作可证伪）：改交付目录 → 新派单的产物出现在新目录；把目录设为不可写 → 界面明确报错并按回落策略处理（不静默丢产物）。

**依赖**：b1 的配置存储与调度（R4a / R4b）先落地。

### R6 打包为 Windows .exe 安装包并可分发〔台账 #6｜批次 b4〕

**模块目标**：把工具打成 Windows 安装包，分享给其他 PC 用户安装使用。

**功能点**

- F6.1 electron-builder 产出 NSIS `.exe` 安装包。
- F6.2 目标机无需安装 Node 或额外浏览器（浏览器运行时随包携带；也可切系统 Edge）。
- F6.3 首次启动引导：打开设置窗口与登录引导，能看到 MCP 地址并复制（接入宿主用）。

**边界**：只做 Windows（x64）；不做自动更新通道（需要时另立需求）；当前不做代码签名（未签名安装包可能触发 SmartScreen 提示，属已知项）。

**验收**

- AC-R6-1（命令可验）：`npm run dist` 产出 `release/` 下的 NSIS 安装包（文件名含版本号，可执行）。
- AC-R6-2（换机操作可证伪）：在另一台 Windows PC 安装 → 托盘启动 → 完成一次端到端派单取件（冒烟）。
- AC-R6-3（操作可证伪）：目标机未额外安装浏览器、未装 Node.js，仍能跑通 AC-R6-2。

**依赖**：b1–b3 功能完成；构建机可访问 npm 镜像与浏览器二进制镜像。

### R7 内置接入说明（面向操作者与 AI-Agent）〔台账 #7｜批次：① 随 b1、②③ 随 b2；④ 的归属见 docs/batches/b1-core-loop.md §2 上抛项〕

**模块目标**：任何 AI-Agent 工具及其操作者，不需要额外讲解，只读内置说明就能完成接入并正确调用本工具。

**功能点**

- F7.1 随包接入说明文档：接入步骤、MCP 配置片段、工具清单、调用示例、排障与人工接管条件（面向操作者，AI 亦可读）。
- F7.2 应用内「接入指引」页：显示当前实际地址 / 端口 / 服务状态，提供一键复制配置，并可打开随包文档（b2）。
- F7.3 可复制的 MCP 配置片段：由应用按实际运行态生成；静态样例在说明文档中，并标注「以应用显示为准」。
- F7.4 给 AI-Agent 的说明文件：服务自述五要素——我是谁 / 我提供什么 / 怎么调用 / 出错怎么办 / 何时需要人来操作。

**边界**：不做在线文档站点；不做多语言（中文先行）；不讲解各外包平台的账号注册流程；不替代宿主自身的 MCP 文档。

**验收**

- AC-R7-1（命令可验）：随包接入说明文档存在，含「接入步骤 / 配置片段 / 工具清单 / 调用示例」四节；文中配置样例可被 JSON 解析，且字段名与 ThinCoder 实测形状一致（`mcpServers` 对象形、`url` 字段）。
- AC-R7-2（陌生 AI 接入，操作可证伪）：把该说明作为唯一上下文交给一个从未见过本项目的 AI（新会话），它能完成配置 → 探活 → 成功派单一次；判据 = outbox 出现新任务目录且 manifest.state = done。
- AC-R7-3（说明与实现一致，命令可验）：给 AI-Agent 的说明文件中的工具清单，与 `tools/list` 实际返回的工具名与数量一致。
- AC-R7-4（不重复维护，人工可检）：四载体内容分工无重复详述（长文只在①、动态信息只在②、片段生成只在③、AI 视角只在④）。

**依赖**：R1 的端点与工具面（说明内容须与实际一致）；b2 界面（②③ 的界面呈现）；b4 打包（随包携带）。

### R8 外包工级开关：深度思考 / 联网搜索〔台账 #8｜批次：配置与应用随 b1、界面随 b2〕

**模块目标**：每个外包工的「深度思考」「联网搜索」两个开关，在**登记 / 设置该外包工时一并确定**，派单时由工具自动对齐——不留给每次临时决定。

**功能点**

- F8.1 每个外包工带两个开关配置：`toggles.thinking` / `toggles.search`（布尔值；默认 false / false）。
- F8.2 派单执行时自动应用：新会话打开后、发送前，把网页端两个开关设为本外包工的配置值（以页面 `aria` / 类名确认切换成功）。
- F8.3 应用结果可核对：发送请求载荷中的 `thinking_enabled` / `search_enabled` 与配置一致（真机实测通道，见批次档 §1 探针 4/5）。
- F8.4 应用失败（开关元素缺失 / 切换后状态不符）按外包工不可用处理（`E_SELECTOR_MISSING` 路径），不静默带错发送。

**边界**：不做「每单临时覆盖」（开关权威 = 外包工设置；如需按任务覆盖另立需求）；不造平台未提供的开关；不改平台账户级默认（只影响本工具发起的会话）。

**验收**

- AC-R8-1（命令可验）：配置 `toggles.thinking=true, toggles.search=false` 派单一次 → 捕获的 `chat/completion` 请求载荷满足 `thinking_enabled=true` 且 `search_enabled=false`；**核对范围 = 受支持子键**（b6 起）：`ok` 按受支持子键全等判定，`payload` 未捕获 ⇒ `ok` 为 `null`（合法路径，不伪装绿）。
- AC-R8-2（操作可证伪）：把某外包工开关改为另一组值 → 再派一单 → 载荷两键随之变化；界面与日志可见应用动作。
- AC-R8-3（命令可验）：开关元素缺失场景（选择器失效）→ 任务走 `E_SELECTOR_MISSING` 处置路径，不发送。
- **无任一受支持子键的平台**（适配器 `capabilities.toggles` 两子键皆不支持）⇒ 跳过开关子步，其 AC-R8-1 / AC-R8-2 / AC-R8-3 不适用；**部分子键受支持**的平台（如 Kimi 的 search）按受支持子键执行——不受支持子键跳过、不报错、不核对（口径同 `docs/design/modules/adapters.md`「外包工开关的应用与核对」末行）。

**依赖**：R3 的适配器与发送链路；平台开关能力（DeepSeek 已实测：`div.ds-toggle-button` + `aria` 可读可设、请求载荷 `thinking_enabled` / `search_enabled` 为权威读法）；b2 界面（开关的呈现位置）。

### R9 换机自适配与端点可改（含主包AI 可自主修复接入）〔台账 #9｜批次：端点与发布面随 b1、界面呈现随 b2、换机验收随 b4〕

**模块目标**：装到另一台 PC 后，本机 MCP 端点自动适配该机（端口 / 路径 / 浏览器 / 登录态）；端点一旦变化，**用户或主包AI 都能把宿主侧配置改对**，不需重新讲解。

**功能点**

- F9.1 端点默认 `127.0.0.1:17873`；端口被占 ⇒ 自动顺延，并在界面与日志明示**实际端口**。
- F9.2 实际地址发布：`runtime.json`（机器可读）+ 设置界面显示 + 一键复制接入片段（`.mcp.json` 与 `config.json` 两种形态，含实际端口）。
- F9.3 端口可由配置文件固定：用户或主包AI 写入期望端口 ⇒ 应用以该端口启动，并把新地址写回 `runtime.json` 与片段（换端口不需改代码或重装）。
- F9.4 换机自适配：目标机无 Node、无额外浏览器也可运行（浏览器随包）；交付目录不可用 ⇒ 按回落策略选可用目录并在界面显示实际路径；每平台首次需人工登录一次，界面给引导。
- F9.5 接入修复路径入说明文档：「换机后首次接入」「端点 / 端口变化后如何更新宿主配置」两节，主包AI 只读说明即可自主完成（与 R7 的说明文档同源，不重复维护）。
- F9.6 接入片段可导出为文件（应用内一键），供用户或主包AI 读取后更新宿主配置（避免手抄）。

**边界**：仍只绑 `127.0.0.1`（不做跳网访问）；不自动改写第三方宿主的私有配置文件（宿主内部格式不承诺）；不做自动更新通道。

**验收**

- AC-R9-1（命令可验）：占用 17873 后启动 ⇒ `runtime.json` 的端口 ≠ 17873，且界面 / 日志显示的实际端口与之一致；按该端口接入可探活成功。
- AC-R9-2（操作可证伪）：把期望端口写入配置并重启 ⇒ 应用以新端口服务；按界面片段更新宿主配置后派单成功（outbox 出现 state=done 的新任务）。
- AC-R9-3（换机操作可证伪）：在一台未装 Node 的 Windows PC 安装 → 首次启动即可按界面显示片段完成接入 → 派单取件一次（与 AC-R6-2 同批执行）。
- AC-R9-4（人工可检）：说明文档含上述两节，且字段与界面实际显示一致。

**依赖**：R1（端点与工具面）、R7（接入说明）、b2 界面、b4 打包。

### R10 会话复用（降低平台风控触发 + 相邻任务上下文连续）〔台账 #19｜批次：b5〕

**模块目标**：同一平台、同一外包工**连续派单时复用同一聊天会话**，减少「每单新建会话」这一平台风控最敏感的动作，并让相邻任务共享上下文。

**功能点**

- F10.1 复用判定发生在**引擎 opening 阶段、新建会话之前**；判定为复用 ⇒ 跳过新建、沿用上一单留下的会话页。
- F10.2 **阶段边界**（任一命中 ⇒ 换新会话）：空闲超过 `session.ttlMs`；本会话累计任务数达 `session.maxTasksPerSession`。
- F10.3 **故障不继承**（任一命中 ⇒ 换新会话）：上一单终态为出错 / 被取消；浏览器上下文被重建。
- F10.4 **配置**：顶层 `session` 块 —— `reuse`（总开关；`false` ⇒ 回到「每单新会话」现状）/ `ttlMs` / `maxTasksPerSession`；由主进程经 `task.run` 入参透传（与 `toggles` 同形，引擎不自行读配置）。
- F10.5 **可观测**：每次判定写一行日志（`复用会话（taskCount=… idleMs=…）` / `新会话（原因=…）`）。
- F10.6 **登录检查不受影响**：每单仍做登录态检查（复用只跳过新建会话，不跳过安全检查）。

**边界**

- 不改 MCP 六件套契约（不加参数、不改返回形状、manifest 不加字段）。
- 不改工单语义（答复仍取「最新一条带结束标记的助手消息」；取件三层不变）。
- 每外包工并发仍为 1；不做跨外包工会话共享；不做跨引擎重启持久化；不做上下文压缩 / 摘要；不做服务端会话有效性预检。
- b5 无设置界面开关（手改 `config.json`）；**b6 起**设置界面提供「会话复用（全局）」块（复用开关 + 空闲 TTL + 单会话任务上限）。

**验收**

- AC-R10-1（命令可验）：连续两单 + 复用开启 ⇒ 引擎侧新建会话调用计数 = 1。
- AC-R10-2（命令可验）：空闲超 TTL ⇒ 计数 = 2；上一单出错 ⇒ 计数 = 2；任务数达上限 ⇒ 计数 = 2。
- AC-R10-3（命令可验）：`reuse=false` ⇒ 每单必新建（回退现状）。
- AC-R10-4（真机 / 人工）：连续两单派单 ⇒ 第二单日志无「新会话」行，且答复 / 取件判据不变。
- AC-R10-5（命令可验）：派单后取消 ⇒ 下一单换新会话（新建计数 = 2，日志含「新会话（原因=canceled）」）。
- AC-R10-6（命令可验）：复用命中时，交付文本 == **本单**回合（不含上一单任何文本）；兜底通道无本单新回合 ⇒ 判 `E_NO_RESPONSE`（不得静默交付旧答复）。

**依赖**：R3 的适配器与引擎接口；`task.run` 入参形（透传先例 = `toggles`）。

### R11 自定义外包工（自由填写名称与链接，接入任意网页版 AI）〔台账 #30｜批次：b7〕

**模块目标**：新增外包工时，除内置平台（DeepSeek / Kimi）外，支持**用户自主填写名称与链接**，把任意网页版 AI 接入为外包工，使工具不被内置清单锁死。

**功能点**

- F11.1 「新增外包工」提供**自定义入口**：自由填写**名称**（列表内唯一，同既有改名规则）与**链接**（网页版 AI 地址）。
- F11.2 自定义外包工走**通用尽力驱动**（best-effort）：引擎以通用启发式定位输入区与发送动作、读取最新一条助手回复；**不承诺**对所有站点稳定，界面上如实标注「实验性」。
- F11.3 工具**只提供接口、不做平台优化**：允许用户自己的主包AI 在派单失败时对**该外包工的驱动参数**（如输入区选择器 / 发送方式 / 回复区选择器）进行补充与修正——即由主包AI 完成「二次优化」；本工具**不实现**自动优化回路。
- F11.4 **可观测**：自定义外包工的派单过程与失败原因沿用既有错误码与日志；失败回执须给出**可交给主包AI 的定位信息**（阶段 + 缺失/不匹配的选择器项）。
- F11.5 **提示与说明随包**：新增界面的自定义入口与该外包工行内，须写明「可由你的主包AI 优化」；随包说明（`docs/guide/`）增补该用法一节。
- F11.6 内置平台行为不变（DeepSeek / Kimi 仍走各自适配器）。

**边界**

- 不做自动优化 / 自学习回路（只留接口，优化由用户的主包AI 完成）。
- 不改 MCP 六件套契约（自定义外包工对主包AI 而言仍是「一个外包工」）。
- 不承诺第三方站点稳定性；不绕过登录与风控（既有全局边界不变）。
- 本批自定义外包工**不含**送件、开关、下载捕获与新建会话（均按不支持处置，界面与随包说明如实标注）。

**验收**

- AC-R11-1（命令可验）：设置面新增自定义外包工（名称 + 链接）⇒ `list_workers` 可见、`config.json` 落盘该 worker（含 url 字段）。
- AC-R11-2（命令可验）：自定义外包工派单 ⇒ 引擎走通用驱动流程（opening → sending → streaming/extracting），并在**驱动参数缺失/不匹配**时以既有错误码 + 定位信息失败（不静默挂起）。
- AC-R11-3（人工）：随包说明含「自定义外包工 + 由主包AI 二次优化」一节；新增界面含该提示。

**依赖**：R3（适配器接口）· R5（设置界面）· R8（自定义平台的子键能力位默认按不支持）。

### R12 自定义外包工补齐（写入轴 · 取答复轴与诊断普查 · 错误码映射 · 补件能力门 · 遮挡处置）〔台账 #34 / #36 / #37 / #38｜批次：b8〕

**模块目标**：把 b7 的自定义外包工从「能接入」补齐到「**常见站点能稳定用**」——按真实站点实测（豆包 ✓ / 元宝 ✗ / 智谱 ✗ / 千问 ✗）暴露的三个轴逐条补齐，并让 F11.3「由用户主包AI 二次优化」在**取答复轴**上真正可操作。

**功能点**

- F12.1 **写入轴**：任务文本写入不得把换行当发送（多行按同一段内容落入输入区）；对富文本编辑器（Slate 类重建 DOM 的站点）采用稳定写入（focus 优先 / 键盘输入 / 元素重定位与有界重试），不再「打标记再点标记」。（覆盖 #37 与千问类）
- F12.2 **取答复轴**：回复候选族扩充（覆盖常见自研前端；判据 = 元宝 / 智谱）；`replySelector` 用户参数继续可用且优先级最高。
- F12.3 **诊断普查**：失败回执除「候选=0」外，须给出**页面上实际存在什么**（同类元素计数 / 可见文本片段 / 高频类名 Top-N），使主包AI 据此定新选择器并重试——F11.3 回路真正闭合。
- F12.4 **错误码映射**：写入类失败不得回落 `E_INTERNAL`；按既有码表映射并保留可定位 message；`needsHuman` 仅在确需人工（登录 / 验证码）时为真。
- F12.5 **补件能力门**：`attach_files` 走与 `task.run` 同一能力门（不支持送件者同步拒绝、不建任务、不置冷却）。（台账 #34）
- F12.6 内置平台（DeepSeek / Kimi）行为不变；MCP 六件套契约不变（工具名/入参/返回形状与错误码**语义**不变，仅映射修正）。
- F12.7 **遮挡处置**（真机文心一言实测：引导弹窗拦截点击）：写入/聚焦**前**探测遮挡并按层级处置（Escape → 关闭钮候选链 → 点蒙层外），**有界（≤3 轮 / ≤4000ms）、幂等、失败不阻断**；失败回执的普查段须报出**遮挡元素**。（台账 #38）

**边界**

- 不新增 MCP 工具或参数；不新增错误码语义。
- 不做站点专用适配器（本批只补**通用**驱动；把某站做成内置适配器属另一批）。
- 不承诺对所有站点稳定（「实验性」口径不变）。

**验收**

- AC-R12-1（真机）：**豆包**单行与**多行**任务均 `done`（覆盖 F12.1）。
- AC-R12-2（真机）：**元宝或智谱至少一台** `done`（覆盖 F12.2）；若仍失败 ⇒ 回执**必须**含 F12.3 的普查读数。
- AC-R12-3（命令 / 真机）：写入类失败的错误码 ∈ 既有码表 ∧ `needsHuman` 不为真（覆盖 F12.4）。
- AC-R12-4（命令）：`attach_files` 对不支持送件外包工 ⇒ 同步拒绝 ∧ 不冷却 ∧ 不建任务（覆盖 F12.5）。
- AC-R12-5（命令）：b1–b7 全套回归无红 ∧ 内置平台真机环通过。
- AC-R12-6（真机）：千问（Slate 类）派单 ⇒ 若 `done` 记读数；若不 `done` ⇒ 错误码 ∈ 既有码表 ∧ 回执含 F12.3 普查 ∧ **不得**为 `E_INTERNAL`。
- AC-R12-7（真机 + 机器）：**文心一言**单行派单不再因遮挡失败（`done`；或失败 ⇒ 码 ∈ 既有码表 ∧ ≠ `E_INTERNAL` ∧ 普查含遮挡元素）；机器 = `/custom-overlay` fixture（链外类名遮挡、仅 `Escape` 可消除）⇒ `done` ∧ 日志词形可判（覆盖 F12.7）。

**依赖**：R3（引擎接入与适配器）· R4a（选人）· R11（自定义外包工）· 台账 #34 / #36 / #37 / #38（本轮真机实测证据）。


## 4. 全局边界（本工具不做什么）

- 不代持账号：不存平台账号密码；登录态只存在浏览器配置目录（该目录不提交、不外传）。
- 不突破平台限制：不做验证码破解 / 风控绕过；遇验证码或风控转人工接管。
- 不做云端中继：能力仅本机（127.0.0.1），不提供公网服务。
- 不做内容审查与二次改写：取回原文原文件，内容质量由网页版 AI 与用户判断。
- 平台服务条款与合规风险由用户自行判断（决策记录见批次档 `docs/batches/b1-core-loop.md` §1）。

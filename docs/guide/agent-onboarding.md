# 「免费外包」接入说明（面向操作者）

> **这份文档是什么**：把「免费外包」接到你的 AI 工具（主包AI / MCP 宿主）上的完整步骤，以及出问题时的处理办法。
> 受众 = 使用本工具的操作者（AI-Agent 也可读；AI 视角的服务自述见 `docs/guide/agent-brief.md`）。
> 文中的端口样例一律用**默认端口 17873**；本工具端口可能因被占而顺延，**实际端口以应用显示为准**。
> 快速分工：① 本文 = 怎么接、怎么调、出错怎么办；④ `agent-brief.md` = 给 AI-Agent 的服务自述；② 应用内「接入指引」页（b2）= 实际地址与一键复制；③ 配置片段生成器（b2）= 按实际端口生成。

## 一、接入步骤

1. **先启动本工具**（安装后从开始菜单启动；开发期 `npm run app`）。托盘常驻，MCP 服务随之启动。
2. **确认实际地址**。去哪里看（三处同源，任选其一）：
   - 托盘菜单「MCP 地址」一行；
   - 文件 `<userData>\runtime.json`，即 `%APPDATA%\free-outsource\runtime.json`，取其中的 `url` 字段；
   - 设置界面「接入指引」页（b2 提供，含一键复制与一键导出）。
3. **在宿主里新增 MCP 服务器**（ThinCoder 桌面版）。两种形态任选一种（样例见第二节）：
   - **形态 B（宿主级·推荐，实测可用）**：**设置 → MCP → 新增服务器** ⇒ **类型选 `http`**（界面这一格的名字就叫 `http`，**不要**选 URL / SSE / stdio）⇒ 地址填 `http://127.0.0.1:<实际端口>/mcp` ⇒ 点 **Test（探活）**（通过时应显示 `OK — 6 tools` 之类）⇒ 保存。
   - **形态 A（项目级）**：在项目根写 `.mcp.json`（`mcpServers` 对象形），由宿主读取。**实测注意**：宿主在**启动 / 装配时**读取该文件——**宿主已在运行期间才写入的话，当前会话的 MCP 段可能不会出现该条目**（本工具实测如此）；这种情况改用形态 B，或重启宿主后再看。
   顺序要紧：**先启动本工具、再在宿主里新增**——宿主会先探活，探活通过才会保存。
4. **探活**。宿主里应显示本工具的六个工具（见第三节）；也可直接确认 `http://127.0.0.1:17873/healthz` 返回 `ok: true`（端口换成实际值）。
5. **派单**。让主包AI 调用 `dispatch_task`（或用宿主界面手动调）：任务文本必填；可指定外包工名、可带本机附件路径、可设置等待秒数。
6. **取件**。产物写在交付目录（默认 `D:\免费外包\outbox`，可在配置 `outboxDir` 修改）下每单一个子目录：`manifest.json`（状态权威）/ `answer.md`（答复全文）/ `files/`（产出文件）/ `inbox/`（附件留证）/ `screenshots/`（失败截图）。

## 二、配置片段

两种形态的样例（**实际端口以应用显示为准**；样例使用默认端口 17873）：

项目根 `.mcp.json`（`mcpServers` 对象形，第二源）：

```json
{ "mcpServers": { "free-outsource": { "url": "http://127.0.0.1:17873/mcp" } } }
```

宿主 `config.json` 的 `mcp.servers`（数组形；**并入**宿主现有数组，不要整文件覆盖）：

```json
{ "mcp": { "servers": [ { "name": "free-outsource", "url": "http://127.0.0.1:17873/mcp" } ] } }
```

- 主推接入路径是 `http://127.0.0.1:<实际端口>/mcp`（Streamable HTTP）；
  另有兼容路径 `http://127.0.0.1:<实际端口>/sse`（旧式 SSE + `POST /messages`），宿主旧客户端可用。
- 授权：默认无令牌（服务只绑 `127.0.0.1`，仅本机可达）。若在配置里设置了 `mcp.token`，宿主条目需带 `Authorization: Bearer <令牌>`（宿主条目支持 `token` / `headers` 字段）。
- 片段里的字段以宿主当前版本的格式为准；拿不准就用应用内一键复制/导出（b2），避免手抄出错。

## 三、工具清单

| 工具 | 用途 | 关键入参 |
|---|---|---|
| `list_workers` | 列出外包工（网页版 AI）与状态：`ready` 可派单；`busy` 正忙（仍可派单，会在其队列排队）；`login_required` / `unavailable` / `disabled` 需人工处理 | 无 |
| `dispatch_task` | 派单（异步）：默认按优先级选人，也可用 `worker` 指定；可带附件；立即返回任务号 | `task`（必填）、`worker`、`files`、`waitSeconds` |
| `get_task` | 查任务状态与阶段；`waitSeconds` 长轮询（≤600，默认 0 立即返回） | `taskId`、`waitSeconds` |
| `fetch_result` | 取回答复文本与文件清单，并给出该单实际交付目录；任务未完成时不返回文本 | `taskId`、`includeText` |
| `cancel_task` | 取消任务：排队中立即取消；执行中尽力停止（已写出的部分产物保留） | `taskId` |
| `attach_files` | 给「尚未发送」的任务补送附件；已发送则报错，应改为新派单 | `taskId`、`files` |

## 四、调用示例

派单（不指定外包工 ⇒ 按优先级；`waitSeconds` 0 立即返回任务号）：

```json
{ "task": "把这段话翻译成英文：今天天气不错。", "waitSeconds": 0 }
```

带附件并指定外包工（外包工名 = 你在清单里设置的自定义名）：

```json
{ "task": "检查这个文件并给出修改建议。", "worker": "DeepSeek", "files": ["D:\\projects\\demo.py"] }
```

查单到终态（长轮询 120 秒；到点未完成会返回当时状态，任务继续跑）：

```json
{ "taskId": "20261009-120000-ab12", "waitSeconds": 120 }
```

取件（答复文本与文件清单；全文总在任务目录的 `answer.md`）：

```json
{ "taskId": "20261009-120000-ab12", "includeText": true }
```

## 五、排障与人工接管

- **任务落 `needs_human`（需人工）**：托盘会弹通知，任务状态也会明示；按提示处理（多为登录或验证码），处理完**点托盘菜单「我已处理（清除外包工冷却）」**，再**重新派单**即可。浏览器窗口是留给人工的，不要提前关掉。
- **看错误码怎么办**（错误码的完整说明（面向 AI 的建议）见 `docs/guide/agent-brief.md`）：
  - `E_LOGIN_REQUIRED`：该平台需要登录——到打开的浏览器窗口完成登录 ⇒ **点托盘菜单「我已处理（清除外包工冷却）」** ⇒ 重新派单。
  - `E_CAPTCHA_OR_RISK`：出现验证码 / 风控——在浏览器窗口里人工处理；处理完**点托盘菜单「我已处理（清除外包工冷却）」即可立即重派**（不点则该外包工冷却默认 10 分钟）。
  - `E_SELECTOR_MISSING`：平台页面结构变化（或外包工开关元素缺失）——任务不发送、留失败截图；需要适配器适配（开发者介入），先留证据再重派。
  - `E_TIMEOUT` / `E_NO_RESPONSE` / `E_SEND_FAILED`：网络或平台波动——工具已自动重试；仍失败可直接重派。
  - `E_OUTBOX_WRITE`：交付目录不可写——检查目录权限与磁盘空间。
  - `E_NO_WORKER`：没有任何可用外包工——检查登录状态与启用开关（`list_workers` 可看）。
  - 其它码：把任务号与 `%APPDATA%\free-outsource\logs\app.log` 中的对应行一起交给开发者排查。
- **产物在哪里**：`<交付目录>\<任务号>\`；状态权威是其中的 `manifest.json`（`state` 终态 = `done` / `failed` / `canceled` / `needs_human`）。失败截图在 `screenshots/`。
- **日志**：`%APPDATA%\free-outsource\logs\app.log`（不记录令牌 / Cookie 等敏感值）。
- **任务卡住/乱套了**：`cancel_task` 取消该单；应用重启后未完成的任务会被标记 `interrupted`（原样保留产物，不自动重跑，需要就重新派单）。

## 六、换机后首次接入

- **目标机无需安装 Node、无需另装浏览器**：浏览器运行时随包携带（也可在配置 `browser.mode = "edge"` 切用系统 Edge）。
- **登录态不跨机**：每台新 PC 上，每个平台都需要人工登录一次（登录态只存在本机 `<userData>\profiles\<外包工 id>\`，不会随安装包迁移，也不外传）。
- **交付目录**：配置值不可用（目录不可写等）时，工具会自动回落到 `%USERPROFILE%\免费外包\outbox`，并把**实际路径与回落原因**记在日志 / 托盘通知里（不静默丢产物；界面显示随 b2）。
- 首次接入步骤：
  1. 安装并启动本工具；
  2. 看实际地址（托盘 / `runtime.json` / 设置界面（b2）实际显示）；
  3. 按第八节把宿主配置里的 URL 更新为实际地址；
  4. 首次派单时工具会打开平台窗口——在窗口里人工登录一次；之后免登；
  5. 探活通过后正常派单取件。

## 七、端口被占怎么办

1. **读实际端口**（服务可能已自动顺延）：托盘菜单「MCP 地址」一行；文件 `%APPDATA%\free-outsource\runtime.json` 的 `port` / `url` 字段（判活用 `pid`，见第八节）；设置界面「接入指引」页（b2）。
2. **改期望端口**：编辑本工具配置文件 `%APPDATA%\free-outsource\config.json` 的 `mcp.port`（默认 17873），**重启本工具后生效**——写入通道就是文件手改（用户或主包AI 都能改；工具面不提供配置读写，见第九节）。
3. **更新宿主配置**：地址变了就把宿主里的 URL 改成实际地址并重连（步骤见第八节）。
4. **终局**：期望端口被占 ⇒ 自动 `+1` 逐级顺延、**最多试到 +120**（默认端口起见：17873 最多试到 17993）；该范围内全被占 ⇒ **MCP 服务不启动**——托盘通知与日志明示「端口不可用」及建议：释放占用端口的程序，或改写 `mcp.port` 后重启。

## 八、端点 / 端口变化后如何更新宿主配置

何时会变化：期望端口被别的程序占用 ⇒ 服务自动顺延到下一个端口；或你（或主包AI）改了配置里的 `mcp.port` 后重启。

怎么发现：托盘提示「MCP 地址已变化，请更新宿主配置」；托盘菜单与日志都显示**实际**地址；`runtime.json` 同步覆写。

怎么更新：

1. 取得实际地址：读 `%APPDATA%\free-outsource\runtime.json`（**字段清单**见下表）；或设置界面「接入指引」页（b2，可一键复制 / 一键导出两种形态的片段）。
2. **先判活**：用 `pid` 字段判定服务是否在跑——该进程不存在 ⇒ 这个 `runtime.json` 是崩溃残留的陈旧文件，以应用实况为准（重新启动应用后以新的为准）。
3. 把宿主配置里指向本工具的 URL 改成实际地址（形态见第二节；宿主内部格式以其版本为准，本工具**不自动改写**第三方宿主的配置文件）。
4. 让宿主重连（重新探活 / 重连 MCP），然后派一条小任务验证全链。

`runtime.json` 字段（文件 = `%APPDATA%\free-outsource\runtime.json`）：

| 字段 | 含义 |
|---|---|
| `pid` | 主进程 PID——判活依据：进程不存在 ⇒ 文件陈旧 |
| `host` | `127.0.0.1`（固定；只绑本机是产品边界） |
| `port` | **实际**监听端口（可能 ≠ 期望端口） |
| `url` | 实际 MCP 端点 `http://127.0.0.1:<实际端口>/mcp`——接入片段引用它 |
| `version` | 应用版本 |
| `startedAt` | 本次启动时间（ISO 8601） |

## 九、本工具端点配置（期望端口）

- 本工具的配置文件：`%APPDATA%\free-outsource\config.json`；期望端口键 = **`mcp.port`**（默认 17873）。
- 改法：用户或主包AI 直接编辑该文件（工具面**不提供**配置读写工具——六件套封闭），**重启本工具后生效**。
- `mcp.host` 固定 `127.0.0.1`（不提供跳网 / 公网访问）。
- 端口冲突规则：期望端口被占 ⇒ 自动 `+1` 顺延（**最多试到 +120**），顺延后按第八节更新宿主配置；+120 内全被占 ⇒ MCP 服务不启动，托盘与日志明示「端口不可用」及建议（释放占用端口的程序，或改写 `mcp.port` 后重启；应急处置见第七节）。


## 十、自定义外包工（实验性）

「自定义外包工」= 你自己填**名称**和**链接**接进来的一台网页版 AI。适合接本工具未内置的站点：填完即可被派单（通用尽力驱动），**不承诺对各站点都稳定**——所以它在界面与本文里一律标注「实验性」。

### 10.1 它能做什么

- 新增：设置 → 外包工 → 新增外包工 →「自定义」→ 填**名称**（清单内唯一）与**链接**（`http` / `https` 开头的完整地址）⇒ 保存后出现在外包工清单里，可被 `dispatch_task` 派单（名字 / id 指定与内置平台同一口径）。
- 驱动方式：**通用尽力驱动**——工具自行在页面里找输入区、发送、回复区；能找到就发、能取回就交付（答复走页面文本采集通道；本单回合按「发送后新出现的回复」锚定，不静默交付旧答复）。
- 回执：与其他外包工同一套工具与状态面（`list_workers` / `dispatch_task` / `get_task` / `fetch_result` …）；答复全文照常写 `answer.md`。

### 10.2 诚实边界（先说清楚不做什么）

- **不承诺站点稳定性**：通用启发式对页面结构有假设；站点改版、类名特殊、整区重渲染都可能让它找不到或取错（实验性残余风险，失败会如实回报，见 10.3）。
- **本批不含以下四项**（界面与回执口径均按「不支持」处理）：
  - **送件（附件上传）**：无通用「上传完成」判据 ⇒ 带附件的派单**不会**发给自定义外包工（显式指定会被同步拒绝；自动选人会跳过它，不会静默发出丢掉附件的任务）。
  - **平台开关**（深度思考 / 联网搜索）：无通用开关控件判据 ⇒ 界面不渲染、引擎不应用（回执里 `toggles.ok` 为 `null`，不伪装成功）。
  - **下载捕获**（页面下载按钮）：取件走既有交付目录通道。
  - **新建会话**：不调用「新建会话」，页内旧回合由本单锚定处置。
- **不绕过登录与风控**：登录墙 / 验证码 / 风控按既有错误码回报，需人工到浏览器窗口处理；工具不会代填凭据、不绕验证。
- 登录态：每台外包工独立浏览器配置目录，登录态**只存本机**、不随包外传；换机后需在该窗口重新登录一次。

### 10.3 失败怎么办：把回执交给你的主包AI

派单失败时，回执给的不是一句「失败了」，而是**定位信息**：出错的**阶段**（opening / sending / streaming）＋ **哪一项没找到 / 没匹配**（含实际值与候选链、采集诊断）。错误码仍是既有那几个（本批不新增错误码），定位信息落在回执的 `message` 里。

典型读法：

| 回执定位 | 含义 | 交给主包AI 的动作 |
|---|---|---|
| `opening：输入区未找到（…候选链…均未命中）` | 页面输入区没被通用启发式命中（已排除登录墙） | 由主包AI 补「输入区选择器」驱动参数 |
| `sending：发送未确认（发送方式=…）` | 输入后没有可观测的发送成功信号 | 由主包AI 补「发送键选择器」或调整发送方式 |
| `发送后未观测到新回复（…采集诊断：候选=…）` | 回复区没命中 / 取不到新回合 | 由主包AI 补「回复区选择器」驱动参数 |
| 登录 / 验证码类错误码 | 需要人工登录 / 处理验证码 | 人工到窗口处理，不是改参数 |

**「二次优化」就是这件事**：本工具不实现自学习 / 自动优化回路——**优化由你自己的主包AI 完成**：把失败回执（阶段 + 未匹配项 + 实际值）交给它，让它修改该外包工的**驱动参数**（见 10.4），再重派一单验证。这是本产品刻意的设计选择：工具只留可自主填写的接口，优化回路留给用户的主包AI。

### 10.4 驱动参数：接口与两条写入通道

驱动参数 = 三个选择器（**空串 = 走通用启发式**，非空 = 覆盖该项）：

| 参数 | 作用 | 空串时 |
|---|---|---|
| 输入区选择器 | 定位输入框 | 通用启发式：`textarea` → `[contenteditable="true"]` → `input[type="text"]`（取最靠下的可见者） |
| 发送键选择器 | 定位发送按钮 | 空 ⇒ 聚焦输入区、写入文本、按 Enter 发送 |
| 回复区选择器 | 定位回复回合容器 | 通用候选链：`[data-message-author-role]` → `[class*="message" i]` → `[role="listitem"]` |

对应配置键（以设置界面实际显示为准）：`driver.inputSelector` / `driver.sendButtonSelector` / `driver.replySelector`。

两条写入通道：

1. **走设置界面（推荐，即时生效）**：外包工行内「驱动参数」入口 → 填三项 → 保存。不需要退出应用。
2. **直接改配置文件**：`%APPDATA%\free-outsource\config.json` 里该外包工条目的 `driver` 三项。**注意**：应用运行中任何界面改动会把内存态整份写回，手改内容可能被覆盖 ⇒ **建议先退出应用再改，改完重启生效**（工具不做文件监听，这是既有口径）。

补充：选择器**语法**不在保存时校验（界面无页面可判定）；语法写错会在下一次派单回执里以「未匹配 + 项名 + 实际值」定位。

### 10.5 三步上手

1. **新增**：设置 → 外包工 → 新增外包工 →「自定义」→ 填名称 + 链接 → 保存；先点「打开并检查」确认登录态与输入区可识别（检查不过先在该窗口人工登录）。
2. **派一单试试**：发一条纯文本小任务（**不要带附件**——本批自定义外包工不支持送件）。
3. **失败就把回执交给你的主包AI**：让它按回执里的「阶段 + 未匹配项」修改该外包工的驱动参数（输入区 / 发送键 / 回复区三项）⇒ 重派验证。工具本身不做自动优化，这一步是预期内的正常流程。

### 10.6 排障速查

- 「打开并检查」显示不可用：detail 即诊断（登录态 / 输入区定位）；先看该浏览器窗口是否停在登录页或验证码页。
- 派单一直不返回：等待上限 = 既有超时参数（默认约 120 秒量级，含自动重试）；到点必失败并回报，不会静默挂起。
- 失败截图：交付目录 `screenshots/` —— 修正选择器的第一手证据。
- 驱动诊断日志：`%APPDATA%\free-outsource\logs\app.log` 中 `自定义驱动诊断：…` 一行（事后取证；日志不含令牌 / Cookie）。

### 10.7 自定义外包工的两个环境坑（实测常见，先看这条再排查）

- **链接要填「聊天工作台地址」，不是品牌落地页**：例如讯飞星火要填 `https://xinghuo.xfyun.cn/desk`（**不是** `https://xinghuo.xfyun.cn/`）。落地页上常有「演示输入框 / 禁用控件 / 营销文案」，通用启发式可能把它们当成输入区（实测：千问落地页的禁用演示框、星火落地页缺输入区都会导致报错）。
- **每个站点要先在它自己的窗口里人工登录一次**：登录态按站点独立存在本机；隔夜/换机后登录可能过期 ⇒ 报 `E_LOGIN_REQUIRED` 或「输入区未找到」这类错时，先看那个浏览器窗口是不是停在登录页。登录后点托盘的「我已处理（清除外包工冷却）」再重派。

### 10.8 给「接入方智能体」的注意事项（把你的 AI 助手接进来之前先看）

- **端点**：以 `%APPDATA%\free-outsource\runtime.json` 的实际地址为准（默认 `http://127.0.0.1:17873/mcp`；被占用会自动顺延，界面与日志都会写明实际端口）。工具只监听本机、不可公网访问。
- **先取名单**：派单前用 `list_workers` 拿「可指定名单」，不要凭记忆写名字；名字即标识（改名就会变）。
- **自带附件时注意**：**内置平台**（DeepSeek / Kimi）支持送件；**自定义外包工一律不支持送件** ⇒ 带附件的派单会被**派单期直接拒绝**（`E_WORKER_UNAVAILABLE`，不建任务、不置冷却，回执会写明「请去掉附件后重派，或改派支持送件的平台」）。
- **失败别硬重试**：回执分两类——**可重派**（如 `E_SEND_FAILED`，瞬时类，可稍后重试）与**需人工**（如登录 / 验证码类，再派也不会成功，要先请人处理）。
- **失败回执里有「普查」**：它会列出页面上实际存在的元素/类名/可见文本（已脱敏）——**把它交给你的 AI 助手改驱动参数**，比反复重派有效。
- **一单一工位**：同一外包工的任务在其自己的队列里排队（并发不会互相抢浏览器）；换人只会因「不可用」发生，不会因「忙」发生。
- **长任务要有耐心**：单笔等待上限是既有超时参数（默认约 120 秒量级），到点必失败并回报，不会静默挂起；超长产出建议拆成多单。

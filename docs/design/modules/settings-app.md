# 模块设计 · 设置界面（b2）

> 职责：设置窗口的页面与交互（外包工管理 / 接入指引 / 交付目录 / 关于）。
> 状态：**b2 实施**；本文给出架构级与交互级设计。配置 schema 见 `docs/design/overview.md`「配置存储」；接入说明四载体分工见同档「接入说明的形态与内容」。
> 不在本文：托盘菜单项与后端服务（`docs/design/overview.md`）、MCP 工具面（`docs/design/modules/mcp-server.md`）。

## 1. 形态与入口

- 独立设置窗口（决策 D），单窗口；托盘菜单：打开设置 / 打开 outbox / 打开日志 / 状态 / 退出。
- **首次启动引导（F6.3）**：`config.json` **首次创建**（即首启）⇒ 自动打开设置窗口并落在**接入指引**页（判据见批次档 b4 §2）。
- 页面：外包工 / 接入指引 / 交付目录 / 关于。

## 2. 外包工页（需求 5 的四件事）

- 每行：平台图标 + 自定义名（可编辑）+ 状态徽标（ready / login_required / busy / unavailable / disabled + 最近检查时间）+ 启用开关 + 上移 / 下移 + 删除。
- 「新增外包工」：先选平台（b1 仅 DeepSeek 可选；Kimi 灰显「待支持」）；默认名 = 平台名，可改。
- 删除：二次确认（提示该外包工的浏览器配置目录保留）。
- 调序：上移 / 下移按钮 ⇒ 直接改 `workers` 数组顺序（优先级单一来源）。
- 改名：列表内唯一性校验；改名即改变「主包AI 指定调用」用的名字（需求 4b）。
- 开关项（R8）：每行两个开关「深度思考」「联网搜索」（配置 `toggles.thinking` / `toggles.search`，默认关），文案标注「派单时自动应用」；改动随其余设置即时落盘（§7）；应用侧规则见 `docs/design/modules/adapters.md`「外包工开关的应用与核对」。
- 状态检查：「打开并检查」按钮——打开 / 复用该外包工浏览器窗口到平台页，刷新登录态显示；未登录（`login_required`）时即**登录引导**：窗口留给人工完成登录，并明示「登录态只存本机，换机后每个平台需重新登录一次」（R9·F9.4）。
- 交互规则：增删改序即时落盘（原子写）+ 即时生效；写入失败（占用 / 权限）弹错并回滚显示。

## 3. 接入指引页（R7 的载体②③；R9 的实际地址 / 复制 / 导出）

- 显示：MCP 服务状态（运行中 / 停止）、**实际 MCP 地址** `http://127.0.0.1:<实际端口>/mcp`（实际端口来源 = 服务实况 / `runtime.json`，见 `docs/design/overview.md`「端口策略与告知宿主」）、备选 `http://127.0.0.1:<实际端口>/sse`、版本号。
- 一键复制（按实际端口生成，权威 = 本页生成器；片段形状见 `docs/design/overview.md`「端口策略与告知宿主」）：
  - 项目根 `.mcp.json` 片段（`mcpServers` 对象形）；
  - 宿主 `config.json` 的 `mcp.servers` 数组形片段。
- 一键导出为文件（R9·F9.6；出口与路径权威 = 本节）：
  - 导出目录 = `<userData>/export/`（界面显示实际路径 + 「打开导出目录」按钮）；
  - `.mcp.json` —— 项目根形态全文（拷到项目根即完成该形态接入）；
  - `mcp-servers.json` —— 宿主 `config.json` 的 `mcp.servers` 数组形片段（读取后**并入**宿主配置；界面文案明示「不要整文件覆盖宿主 config.json」）；
  - 每次导出按实际端口重新生成、覆盖刷新同一文件。
- 打开随包文档 `guide/agent-onboarding.md`（b4 随包后可用；仓库开发期指向 `docs/guide/`）。
- 页内明示接入顺序：「先启动本工具 → 再在宿主里新增 MCP 服务器（宿主探活通过才会保存）」——与宿主「先探活后落盘」的实测行为一致。

## 4. 「按主包AI 要求指定调用」的界面体现（需求 4b）

- 列表条目名 = 主包AI 指定调用时的标识；页面文案明示「主包AI 派单可指定外包工名；仅列表内已启用的外包工可被指定」。
- 未登记的平台不可被指定（接口层拒绝，见 `docs/design/modules/mcp-server.md`「参数校验要点」）。

## 5. 交付目录页（R5·F5.7）

- 显示「当前实际交付目录」——**实际路径**（解析口径见 `docs/design/modules/outbox.md`「目录结构与实际路径」）：配置值可用即配置值；不可用 ⇒ 显示回落路径并标注「已回落：<原因>」。
- 修改：目录选择器；提交前校验（存在或可创建 ∧ 可写），校验失败 ⇒ 界面明确报错、不落配置（不静默接受）。
- 「打开目录」按钮（打开实际路径）；修改即时落盘、即时生效（§7）。
- 运行期目录不可用的报错与回落（不静默丢产物）见 `docs/design/modules/outbox.md`；本页在回落发生时同步显示实际落点。

## 6. 关于页

- 版本号、日志目录路径与「复制日志路径」按钮。

## 7. 配置同步

- 渲染进程只经 IPC：`fo:snapshot` / `fo:patch`（**通道名以此为准**——八方法各自的通道常量与 `window.fo` 暴露面同处 `src/settings/preload.cjs`，跨面改动须两处同步）；主进程负责校验、原子写、广播变更（单一写者）。
- 手改 config.json：下次启动生效；不做文件监听（避免读入半写状态）。

## 8. 验收判据（b2）

- AC-R5-1..6 的操作判据（AC-R5-6 两段复现：① 界面侧 = 选不可写目录提交 ⇒ 界面明确报错、**不落配置**（§5 提交前校验）；② 运行期侧 = 先配置可用目录、再令其不可写（撤权 / 拔盘）后派单 ⇒ 回落 + 托盘 / 日志 / 界面明示（不静默丢产物；复现步骤与回落口径见 `docs/design/modules/outbox.md`）；另：改交付目录 → 新派单产物落新目录）；AC-R7-2 的界面侧（地址显示与一键复制可用）。
